# CodeQL Security Fixes Design

## Goal

Resolve the three CodeQL alerts currently reported for `Short-video-platform`
without changing the application's intended behavior or broadening the scope to
unrelated refactoring.

## Changes

### Database restore path validation

The restore endpoint currently combines the backup directory with a
user-controlled basename. Replace this implicit restriction with an explicit
resolver that:

- accepts only filenames generated by the backup endpoint;
- selects the candidate only from server-enumerated direct children of the
  configured backup directory, so request data never constructs a path;
- rejects symbolic links;
- requires the selected backup to be an existing regular file;
- rejects invalid selections before invoking the `mysql` subprocess.

The route will display a generic failure message for an invalid selection and
will not disclose arbitrary filesystem paths.

### Flask debug mode

Remove the hard-coded `debug=True` development-server setting. Running the
module directly will start Flask with debugging disabled. Developers who need
debugging can use Flask's standard development configuration outside committed
production defaults.

### GitHub Actions token permissions

Add a workflow-level `permissions` declaration granting only `contents: read`,
which is sufficient for checkout and test execution.

## Testing

- Add unit coverage for valid backup paths, malformed filenames, nonexistent
  files, and traversal-like input.
- Add a regression check proving the committed Flask entry point does not enable
  debug mode.
- Run the complete Python unit-test suite and syntax check.
- After pushing, wait for CI and CodeQL and verify that all three alerts close.

## Scope

This change will not redesign backup storage, change database credentials,
alter authentication, or add new application features.
